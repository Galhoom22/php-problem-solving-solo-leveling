# 03 — Strict Progression Law

> AI load this before placing or reordering any Gate. Harder-before-easier is forbidden.

## 1.6 Strict Progression Law (Non-Negotiable)

### The Law
1. **Ascending difficulty only** in any required sequence.
2. **No harder-before-easier** inside the same pattern folder.
3. **No rank skipping** in the recommended path (E → D → C → B → A → S).
4. **Dependencies first**: hashing before problems that assume hashing fluency, etc.
5. **New imports must be insertion-sorted** by difficulty, not appended randomly at the end of an early folder.
6. Optional side quests are labeled `Side Quest` / `Hidden Quest` and must still show Min Hunter Rank.

### Ordering Checklist (run before adding any Gate)
```
- [ ] PHP Fitness Filter passed (`19-php-fitness-filter.md`)
- [ ] Gate Rank mapped (E/D/C/B/A/S)
- [ ] Min Hunter Rank set
- [ ] Pattern prerequisite Gates already exist earlier (or are marked none)
- [ ] No easier Gate appears after this one in the same required path
- [ ] No Medium/Hard placed in E-Rank Skill Books
- [ ] Not linked-list pointer theater / heavy CP structure (unless Side Quest)
- [ ] Source platform + URL recorded
- [ ] Backend Link present
- [ ] XP matches Gate Rank table
```

### Curriculum Placement Test
Ask:
> “If a fresh E-Rank hunter follows the recommended path in order, will Gate N always feel equal or harder than Gate N-1 — never easier by surprise?”

If no → reorder before merging.

### Soft vs Hard Path
- **Hard Path (default recommended)**: strict order, Association locks.
- **Soft Path**: hunter may open a higher Gate with System Warning, but the README order and progress checklist stay strictly progressive (no rewriting history to pretend the hard Gate was “early”).
